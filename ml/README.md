# ml/ — Пайплайн ML-инженерии (Фаза 1)

Здесь живёт всё, что относится к подготовке данных и обучению модели:
ETL теоретического архива ТРИЗ, генерация синтетических датасетов (SFT/DPO),
тонкая настройка (QLoRA) и оценка качества.

## Этап 1. Data Engineering & ETL

- Парсинг неструктурированного архива статей по ТРИЗ (`beautifulsoup4`, `trafilatura`).
- Нормализация старых кодировок (`CP1251` → `UTF-8`).
- Смысловая сегментация и извлечение атомарных правил/эвристик/примеров критики
  в строгие JSON-схемы (`pydantic`).

## Этап 2. Генерация синтетического датасета

- Модель-учитель (`litellm` + `instructor`) генерирует обратные задачи из реальной
  инженерии и бизнеса на основе каждой статьи.
- **SFT-датасет** (500–1000 записей): `Сырая проблема → Очистка от жаргона →
  Физическое противоречие → ИКР → Разбор`.
- **DPO-датасет** (Preference Pairs):
  - `Chosen` — сильный некомпромиссный ход на внутренних ресурсах системы.
  - `Rejected` — банальный компромиссный совет в стиле стандартного ChatGPT.
- Ручная вычитка «золотой сотни» (150–300 эталонов).

## Этап 3. Обучение и оценка

- База: открытая модель 7B–14B (Qwen / Llama).
- Стек: `PyTorch` + `Unsloth` + `Hugging Face TRL` (QLoRA: SFT → DPO).
- Железо: RTX 4090 на RunPod / Vast.ai (~$0.40/час).
- Оценка: `DeepEval` / `LLM-as-a-Judge` (метрика «устранение противоречия без
  усложнения системы», «До / После»).
- Мониторинг: `Langfuse`.

## Целевая структура

```
ml/
├── etl/            # скрипты очистки и нормализации архива
├── synth/          # генерация SFT/DPO датасетов (instructor)
├── train/          # Unsloth + TRL, QLoRA
├── eval/           # DeepEval / LLM-as-a-Judge
└── data/           # исходники и артефакты (gitignored, кроме схем)
```

> Скрипты появятся по мере выполнения Фазы 1 чек-листа из `README.md`.
